Thanks for the detailed report, this is useful. Going through each:

1. **ML-KEM-1024.** The generator does create a 1024 key when you pick that option, but our own key-detection then can't tell a v5 ML-KEM-1024 from a 768 one, because LibrePGP gives both the same algorithm number and they differ only by curve. So it mislabels the key as 768. The key material is very likely genuinely 1024; the label is wrong. If you inspect the generated key with sq and it shows Kyber-1024 + X448, that confirms it. I'm fixing the detection to read the curve and report the right level. If sq shows 768, tell me, because that would mean something different.

2. **RSA 8192 shown as 4096.** Confirmed, and it's the same underlying cause: we were labeling RSA by its algorithm number, which doesn't carry the key size, and defaulting to 4096. The key itself is fine; the label is wrong. Fixing it to read the actual modulus size.

3. **ML-DSA User IDs.** Confirmed. These composite keys are handled specially because the usual library can't hold them, and multi-User-ID support wasn't wired through: the parser reads them all, but only the first is stored and shown, and adding one needs a post-quantum self-signature that isn't in place yet. Showing all of them is the near-term fix; adding a User ID is more work but on the list.

4. **Custom key servers.** Agreed, and it matches what the desktop version already does. Planned.

5. **Granular key creation and post-quantum subkeys.** The engine to attach a post-quantum subkey to an existing key already exists, it just isn't offered in the add-subkey screen yet (that currently lists classical only), so exposing it is a near-term win. A full advanced mode where you pick each subkey by hand is a bigger piece, but I like the idea and will look at it.

Fixes for the two labeling bugs are coming soon; the User ID work and the two features are lined up for the next feature release. Thanks again for the precise breakdown.

An update on the 4.5.0 items from your report, all in 4.5.0-RC2 now.

Custom key servers: you can add your own HKPS servers in Settings and look up and publish through them, and they ride the offline and Tor switches like the built-in ones.

Granular key creation and post-quantum subkeys: the add-subkey screen now offers post-quantum ML-KEM subkeys, not just classical, so you can attach one to an existing key. There is also a granular keygen path where you pick the subkeys by hand, including leaving off the default classical encryption subkey for a post-quantum-only key.

ML-DSA User IDs: composite ML-DSA keys now show all of their User IDs, not just the first, and you can add a User ID, which builds the composite self-certification that was missing before.

The two labeling fixes, ML-KEM-1024 and RSA sizes, went out in 4.4.1 as noted above.

Installs over your current build, no uninstall:
https://pgpony.app/rc/4.5.0-RC-foss/PGPony-4.5.0-RC2-foss.apk

If you exercise any of these, especially the multi-User-ID composite keys against sq or gpg, I would value the feedback.
