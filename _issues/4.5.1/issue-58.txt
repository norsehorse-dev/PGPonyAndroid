Confirmed, and stripping it is the right fix. The share-from-browser path hands us the selected text plus the page's extra markup, and right now import expects the input to be just the key, so the extra characters trip it. Copy-paste and shared .asc files skip that because they arrive clean.

The fix is to pull the armored block out of whatever is shared, between the BEGIN and END PGP lines, and ignore everything around it, so a select-all-and-share imports the same as a clean paste. Handling more than one block in the payload comes with it.

It is in for the next release. Thanks for pinning down exactly which path adds the noise.

This shipped in 4.5.0-RC2.
