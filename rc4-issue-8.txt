Thanks for the report, and glad the app is useful to you.

You've diagnosed it correctly. The passphrase prompt is a Compose text field, and
Compose doesn't expose anything to the autofill framework unless the field is
explicitly annotated for it. OpenKeychain uses a classic EditText with
inputType=textPassword, which the framework's heuristics pick up for free. So
there is genuinely nothing for KeePass to match against, hence the Magikeyboard
fallback.

The fix is to annotate the fields with autofill content types, and to make sure
the prompt on the provider path gets the same treatment and not just the in-app
one, since they're separate code. It needs a Compose version bump to reach the
current autofill API, so I'm planning it for 4.1.0 rather than a patch release.

One thing to be aware of, and it matters more than the autofill: F-Droid is still
on 4.0.0, which is almost certainly what you have. There was a bug in the OpenPGP
provider path on release builds where R8 renamed a parcelable in the API result
intent, and it crashed the calling mail client on decrypt. It affects 4.0.0
through 4.0.3. It's fixed in 4.0.4, verified on a minified release build and
confirmed by another FairEmail user on his own device.

4.0.4 is on GitHub and pgpony.app now; F-Droid will pick it up on its own
schedule. If you want it sooner, the caveat is that an F-Droid install and a
direct download are signed with different certificates, so it means backing up
your keyring, uninstalling, and installing fresh. Entirely reasonable to just
wait for F-Droid instead.

Two things that would help me:

1. Which Android client are you opening the kdbx with, KeePassDX or
   Keepass2Android? Their matching behaviour differs and I'd rather test against
   the one you actually use.

2. Do you hit the passphrase prompt only through FairEmail, or also inside PGPony
   directly? Both need fixing, and they are different screens, so knowing which
   one matters to you tells me what to get right first.

If you've hit anything else beyond the autofill annoyance, I'd like to hear it.

Thanks again for the detail in the report.
