Thanks so much for the kind words, and for the clear report — this is a real one.

Short version: post-quantum keys are big. A v6 ML-KEM key carries a lot more data than a classic key (the ML-KEM public key alone is over 1 KB), and a single QR code has a hard ceiling on how much it can hold — roughly 3 KB. A full ML-KEM v6 public key lands right at that ceiling, so once you add a name, email, or expiration date it can genuinely exceed what one QR code is physically able to encode. That's what "data too big" is telling you.

In the meantime, the Copy and Share buttons on the same screen aren't size-limited — those will move the full key reliably, so you can send it as a file or paste it anywhere. QR is currently best for the smaller classic keys.

I'm tracking a proper fix for the 4.1.0 release. The likely direction is a multi-part / scannable-sequence QR so large PQC keys can still transfer by camera. I want to be upfront, though: a single static QR may never be able to hold a full post-quantum key — so the fix is really about splitting it across codes rather than cramming it into one. I'll update this issue as that lands. Thanks again for helping make the app better.
